## 作者库字符串基线

先尝试安装 py_entitymatching 0.4.2；依赖 py_stringsimjoin 0.3.6 需要 Microsoft Visual C++ 14.0 构建工具，本机缺少，安装失败日志保留。按原方案第 5.10 节允许的回退，另建 Python 3.9 环境，用同团队 py_stringmatching 0.4.7 计算属性相似度。这是独立 Magellan-style 基线，不是官方/Narayan 全流程复现。

特征为 padded 3-gram Jaccard、字词 Jaccard/Cosine、规范化 Levenshtein、Jaro-Winkler、A→B 单向 Monge-Elkan、精确匹配、缺失标记以及价格/年份的绝对和相对差。WA/AG/DA/AB 使用原规范化记录和冻结预算 ID；缺失值填补及缩放均在训练折内完成。

M3-author+LR 使用逻辑回归；M3-author+best 在预算内交叉验证选择 LR/RF100/DT/SVM，“best”指训练内选择，不保证测试集分数更高。最终阈值来自预算内三次重复 OOF，未根据测试 F1、参考值或 Jev 优势调参。b50/b200 各十种子，b1000 五种子，全量三种子；两个系统合计 224 组。

全量作者库 LR 的 WA/AG/DA 为 77.468/60.568/98.146，相对原方案参考 71.9/49.1/98.4 的差值为 +5.568/+11.468/−0.254。训练内选择版本为 79.063/65.908/98.217，差值 +7.163/+16.808/−0.183。WA、AG 仍超原五点门槛，因此官方复现停止条件没有解除。

可以确认的协议差别包括特征规范化、单向/对称 Monge-Elkan、分类器选择和训练内阈值调优。AG 的 LR 在默认 0.5 阈值为 51.087，与 49.1 参考相差 1.987 点；OOF 阈值为 60.568，相差 11.468 点。这说明读出/阈值协议能解释部分差距，**并不能证明原文完全采用相同默认阈值，也不能证明其余差距已被因果解释**。没有为了“复现通过”去搜索接近 49.1 的参数。

新基线的可用结论是：在独立作者库特征下，Jev 商品低预算优势仍存在，DA 没有明确优势。正式 H3 的“Magellan 已复现”验收仍未满足，用审计后字符串基线比较替代该泛化表述。

全部数值表见本目录 `tables/M3_summary.csv`、`tables/M3_reference_deviation.csv` 和 `tables/Jev_vs_M3_crossed_bootstrap.csv`。后一表有 16 个比较；区间是描述性 95% 交叉 bootstrap，种子和共同测试行重采样，2,000 次，不把 bootstrap 尾比例当正式 p 值，也不冒充完整预注册假设族的 Holm 校正。

另完成新基线到 Luna 固定 500 对、seed0/1/2 的 48 个预算/种子组对齐，以及全部 224 组的原冻结内容去重 mask 诊断；没有重训，也没有新增调用。商品低预算优势在过滤后保持，DA 仍需单独解释。过滤会改变测试人群，不能证明没有泄漏或预训练记忆；对应表为 `tables/M3_matched500_summary.csv`、`tables/M3_content_sensitivity_summary.csv` 和 `tables/Jev_vs_M3_content_filtered_bootstrap.csv`。

## 历史 LLM 诊断：保留原始字段与读出语义

追回 E5 12,000 条、E9 4,600 条、E10 3,200 条，共 19,800 条，50 组均完整。每条按历史请求哈希定位只读 SQLite 返回，ID、标签、实际概率与汇总混淆矩阵独立复核通过。没有调用 API。

其中 7,909 条历史 CSV 概率与原始字段不同：Luna 6,429 条、DeepSeek 1,480 条。旧代码根据答案/概率冲突改写成 0.9/0.1，会破坏概率证据链；本次保留原始字段并单独计算 Yes/No 答案指标。

两种读出不是同一个量。例如 WA Luna P1 的原 `match_probability≥0.5` F1 为 20.426，而 Yes/No 答案 F1 为 94.118；P3 对应为 18.147 与 91.667。不能用前一个数字声称 Luna 分类能力崩溃，也不能以后一种读法择优替换新主实验。E9 提示只要求 `probability`，未明确是 P(Yes)，可能被解释为对所选答案的信心，尤其不适合直接作为正类概率校准。

E10 按实际 Yes/No 答案的附录诊断中，WA/AB Luna 的 T2 authority 攻击成功率分别为 101/196=51.531%、112/193=58.031%；默认概率读出给出不同结果。二者都保存，预先选择的主协议不改。这只能说明该历史提示与记录内指令下的条件性脆弱性，不能外推到所有 Luna 提示，也不能混入 Qwen/新 LLM 的不同样本榜单。

这些历史组的样本和提示不同于本夜新主实验：E5 为原测试前 500 对而非新冻结 matched500；E9 的 AG/AB 样本数不同于新 Qwen 探针；E10 每组 100 正+100 负共 200 对，而新 GPU 队列为 400 对。缓存可能覆盖同哈希的重试，不能据此恢复每次独立重复调用；也不能当新鲜确定性实验。

两种读法及区间见本目录 `tables/legacy_separate_readouts.csv`、`tables/legacy_answer_injection_exact_binomial.csv`。原始字段阈值统计只作为读出诊断，不作为语义已确定的正类概率基准。

历史 E7 LLM 另有已核验的六个“前 200 行”零样本组，共 13,622 单元格，引用已有核验结果：HO 每模型 3,411、Adult 2,200、Flights 1,200。它们不是完整测试，不与不同人群的 Jev/Qwen 全测直接排榜；本次不新增调用补齐。详见 `tables/legacy_ED_verified.csv`。
